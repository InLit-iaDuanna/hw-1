# Technical Roadmap Dashboard v3.0

Compass Gait Passive Walking 项目的现代化交互式看板 — 全功能分析平台。

## 使用方式

直接用浏览器打开 `index.html`。无需服务器、无依赖、纯静态。

## 🎯 核心功能（v3.0 新增）

### 1️⃣ 六大视图模式
- **📋 Grid View**（默认）：信息密集型卡片网格，内联显示关键指标和发现
- **📅 Timeline View**：按 Phase 分组的时间线，清晰展示项目演进
- **🔗 Graph View**：交互式依赖关系图，支持平移、缩放
- **⚖️ Compare View** ⭐NEW：版本对比面板，支持 2-4 个版本并排对比
- **📈 Trends View** ⭐NEW：能量效率与性能趋势可视化
- **🔥 Heatmap View** ⭐NEW：参数敏感性热力图分析

### 2️⃣ 版本对比分析（Compare View）
- 选择 2-4 个已完成版本进行并排对比
- 自动提取关键指标：CoT、成功率、Floquet 乘子、前进距离
- 并排显示描述、发现、标签、依赖关系
- 快速识别不同控制律/机构设计的性能差异

### 3️⃣ 能量与性能趋势（Trends View）
- **CoT 演化曲线**：跨版本能量效率趋势，自动标注 Phase 颜色
- **成功率柱状图**：直观对比不同版本的稳定性
- **Phase 时间线**：每个阶段完成版本数量与分布
- 悬停显示详细数值，快速定位关键转折点

### 4️⃣ 参数敏感性热力图（Heatmap View）
- **V13 参数空间扫描**：foot_radius × leg_length 6×6 网格，成功率 16.7%
- **V13.6 FSM 控制器**：同参数空间，成功率 11.1%，成功域迁移到中央
- **V14c 摆臂质量敏感性**：arm_mass 单调退化模式
- **V16 摩擦共振带**：τ_C 非单调模式，失败带 [0.013, 0.20]
- 点击单元格显示详细参数信息

### 5️⃣ 实时统计仪表盘
- 左侧边栏：全局进度统计、Phase 完成度可视化
- 自动计算：完成数、进行中、已规划、总体进度百分比

### 6️⃣ 强大的筛选系统
- 按**状态**筛选：Done / In Progress / Planned
- 按**阶段**筛选：Phase 1-4
- 按**被动性**筛选：Yes / No / Partial 等
- **实时搜索**：支持 ID、标题、描述、发现、标签全文搜索

### 7️⃣ 智能指标提取
- 自动从 `findings` 字段提取：
  - **CoT 值**：匹配 `CoT=0.072` 或 `CoT: 0.072`
  - **成功率**：匹配 `5/36` 或 `14/35` 格式
  - **Floquet 乘子**：匹配 `max|lambda|=0.944`
  - **前进距离**：匹配 `forward=4.87m`
- 自动填充到对比面板和趋势图

### 8️⃣ 信息密度提升
- 卡片内联显示：日期、Phase、被动性、关键指标（CoT、成功率）
- 关键发现直接显示在卡片底部（Done 状态）
- 标签可视化：最多显示 4 个标签 + 数量提示

### 9️⃣ 更好的视觉编码
- Phase 用左侧彩色边框标识
- 状态用徽章颜色编码（绿/黄/灰）
- Timeline 视图用时间轴节点颜色表示状态
- Graph 视图用外圈光晕表示状态

### 🔟 响应式详情面板
- 点击任意卡片/节点打开右侧滑出面板
- 完整信息：描述、发现、元数据、标签、依赖链
- 依赖关系可点击跳转
- ESC 或点击关闭按钮退出

## 如何更新

每次完成新版本或状态变化时，编辑 `data.js` 中的 `VERSIONS` 数组（**不是** `index.html`）。

### 1. 标记版本完成

找到对应版本对象，修改字段：

```javascript
{ id:"V17", ..., status:"done",  // "planned" → "next" → "done"
  folder:"v17_sensor_closed_loop",
  date:"2026-06-15",
  findings:"Your actual findings here",
  ... }
```

### 2. 添加新版本

在对应 Phase 的位置追加新对象：

```javascript
{ id:"V17.1", phase:2, title:"标题", status:"done", passive:"no",
  folder:"v17_1_folder_name", date:"2026-06-XX",
  desc:"这个版本做了什么，为什么做，目标是什么。",
  findings:"关键发现和结论。",
  deps:["V17"], tags:["tag1","tag2"] },
```

### 3. 添加/更新决策门

在 `GATES` 数组中修改或追加：

```javascript
{ after:"V17", text:"决策门描述", status:"passed" },  // "passed" or "pending"
```

### 4. 字段说明

| 字段 | 说明 |
|------|------|
| `id` | 版本号（显示用） |
| `phase` | 1-4 对应四个阶段 |
| `title` | 简短标题 |
| `status` | `done` / `next` / `planned` |
| `passive` | `yes` / `no` / `partial` / `analysis` / `display` / `tbd` |
| `folder` | 对应的文件夹名 |
| `date` | 完成日期 |
| `desc` | 详细描述（1-3 句，说清做了什么、为什么、目标） |
| `findings` | 关键发现（结论性描述，可以长一些） |
| `deps` | 上游依赖版本列表 |
| `tags` | 标签（用于快速识别领域） |

## 🔧 技术特性

- **纯静态**：HTML + CSS + Vanilla JS，无框架依赖
- **响应式布局**：适配不同屏幕尺寸
- **性能优化**：CSS 变量、事件委托、高效 DOM 操作
- **可扩展**：模块化代码结构，易于添加新视图

## 📝 更新约定

- 每个新版本完成后同步更新 `data.js`
- `desc` 写清做了什么 + 为什么 + 目标
- `findings` 写结论性发现，包含量化指标（CoT、成功率等）
- 同一时间只保留一个 `next` 状态的版本（当前焦点）
- 决策门必须标注 passed/pending

## 💡 推荐工作流

### 场景 1：论文答辩准备
1. **Timeline View** → 展示完整研究路径（V01→V25）
2. **Trends View** → 突出 CoT 改进曲线（V10: 0.072 接近人类水平）
3. **Heatmap View** → 展示决策门证据（V13 窄盆地 → V13.6 FSM 迁移）
4. **Compare View** → 对比关键转折点（V10 vs V13.7 摩擦补偿）

### 场景 2：控制律调优
1. **Compare View** → 选择 V10, V13.6, V13.6.1, V13.7
2. 对比 CoT、成功率、Floquet 乘子变化
3. **Heatmap View** → 查看 V13.6 vs V13.6.1 参数域迁移
4. 识别最优控制律配置

### 场景 3：硬件选型（电机摩擦）
1. **Heatmap View** → 打开 V16 τ_C 共振图
2. 识别失败带 [0.013, 0.20] 和成功带 {0, 0.034, 0.27+}
3. **Compare View** → 对比 V16 (失败) vs V13.7 (补偿成功)
4. 决策：选择低摩擦电机或使用前馈补偿
