# 硬件 V1 — 步态检测设备技术栈

**状态**：技术栈确定（待接线/固件）
**日期**：2026-06-13
**定位**：偏瘫患者步态**检测**设备 —— 纯传感，不做任何介入/辅助/驱动
**接续**：V17 状态估计算法（PC 侧复用）

> **范围红线**：硬件 V1 **只做检测**。不装电机、不做辅助、不矫正、不驱动患者。主动介入推迟到后续硬件代次。

---

## 1. 设计目标

采集偏瘫步态的核心评估数据，输出到 PC 做离线/在线分析：

| 临床指标 | 来源 |
|---|---|
| 时空对称性（患/健侧 stance/swing 时间差） | 双足 IMU + gait event 检测 |
| 足下垂（foot drop，heel-strike 时足部 pitch） | 双足 IMU |
| 患侧膝/踝活动度下降 | 双小腿 IMU |
| 躯干代偿 / hip hiking / 侧倾 | 骨盆 BMX055 |
| 左右坐标系对齐基准（绝对航向） | 骨盆 BMX055 磁力计 |

## 2. 硬件清单（V1 实际使用）

| 部位 | 传感器 | 接口 | 说明 |
|---|---|---|---|
| 左足 | BMI160 | I2C（经 mux） | 足部姿态、gait event、足下垂 |
| 右足 | BMI160 | I2C（经 mux） | 同上 |
| 左小腿 | BMI160 | I2C（经 mux） | 踝角度代理、摆动速度 |
| 右小腿 | BMI160 | I2C（经 mux） | 同上 |
| 左大腿 | BMI160 | I2C（经 mux） | 髋/膝角度（与小腿配对出膝角）|
| 右大腿 | BMI160 | I2C（经 mux） | 同上 |
| 骨盆 | **BMX055**（9DOF） | I2C（经 mux 独立通道） | 躯干代偿 + 绝对航向锚点 |
| 主控 | **ESP32-S3** ×1 | — | 采集 + USB 上传 PC |
| 通道扩展 | **TCA9548A** ×1 | I2C 0x70 | BMI160 只有 0x68/0x69，靠 mux 隔离多颗 |

**决策（2026-06-13）**：V1 增配双大腿 IMU（6×BMI160），换取**完整 sagittal 关节角**（膝 = 大腿 pitch − 小腿 pitch，髋 = 大腿 pitch − 骨盆 pitch）。临床层基准改用**文献正常值**，不用 V10 仿真值。

**V1.1 决策（2026-06-14）**：新增单 ESP32-C3 卫星节点测试。C3 直连 1 个 BMI160，通过 ESP-NOW channel 1 发给腰部 ESP32-S3 hub，先映射到 `left_foot`；S3 继续用 USB 串口输出兼容 `45×int16` 聚合帧，并额外输出节点调试帧。

**本次未用（留作备件 / 后续扩展）**：
- ESP32-S3 ×1、ESP32-C3 ×2 —— V1.1 先用 1 个 C3 做无线 IMU 采集测试
- BMI160 ×4 —— 备件 + 可选扩展（双臂摆臂 / 躯干）
- TCA9548A ×1 —— 备件
- ADS1115 ×2 —— **V1 暂不接 FSR，足底事件先用 IMU 算**，ADC 留待后续鞋垫方案
- FSR 鞋垫 —— **V1 不做**

## 3. 系统架构

```
            ESP32-S3 (腰部 hub)
              │  I2C 主线 (0x70)
              ▼
          TCA9548A (1→8 mux)
   ┌────┬────┬────┬────┬────┬────┬──────────┐
  CH0  CH1  CH2  CH3  CH4  CH5   CH6
  左足  右足 左小腿 右小腿 左大腿 右大腿 骨盆BMX055
 BMI160 ...  ...   ...   ...   ...  (gyro 0x68，独立通道避免与BMI160撞址)
              │
              ▼
         USB Serial → PC (V17 算法 / 记录)
```

- **单 MCU + 单 mux**：单一时间基准，**零无线同步**，固件最简单，左右相位天然对齐
- **不上无线**：ESP-NOW 多节点同步留给"自由行走/带回家"那一代

---

## 4. I2C 地址规划

| 器件 | 地址 | 位置 | 备注 |
|---|---|---|---|
| TCA9548A | 0x70 | I2C 主线 | mux 本体 |
| BMI160 ×6 | 0x68 | mux CH0–CH5 | 每颗独占一个 mux 通道，地址可全用 0x68 |
| BMX055 (gyro) | 0x68 | mux CH6 | 与 BMI160 撞址 → **必须单独占一个通道隔离** |
| BMX055 (accel) | 0x18/0x19 | mux CH6 | 同上 |
| BMX055 (mag) | 0x10/0x13 | mux CH6 | 提供绝对航向 |

**操作规则**：每次访问前先写 mux 选通寄存器选中目标通道，用完不必强制关闭但建议逐通道轮询，避免地址串扰。

---

## 5. 采样与数据

| 项目 | 设定 | 理由 |
|---|---|---|
| 采样率 | 200 Hz | 步态运动学 100–200Hz 足够，BMI160 可达 1600Hz 但不必拉满 |
| 时间戳 | MCU 本地 `micros()`，单基准 | 单 MCU 无需跨节点同步 |
| 传输 | USB CDC Serial，二进制帧 | 比 WiFi 稳，实验室阶段优先可靠性 |
| 帧格式 | `[ts, ch0_axyz_gxyz, ... ch5_axyz_gxyz, bmx_axyz_gxyz_mxyz]`（6×6 + 9 = 45 个 int16）| PC 侧解析 |

## 6. 软件栈

| 层 | 选型 |
|---|---|
| MCU 固件 | ESP-IDF 或 Arduino-ESP32（I2C 轮询 mux + USB CDC 上传）|
| 传感器驱动 | BMI160 / BMX055 寄存器级读取（或现成库）|
| PC 接收 | Python（pyserial）→ 复用 **V17 状态估计**算法 |
| 分析 | 复用 `common/` 库（gait event、对称性、能量口径一致）|

## 7. 已知陷阱

1. **BMX055 与 BMI160 撞址（都用 0x68）** → BMX055 必须单独占一个 mux 通道
2. **不要从腰部走 I2C 长线过踝关节** → V1 线沿小腿走，传感器只到小腿，不过踝；足部 IMU 尽量短线就近
3. **mux 通道切换要等总线稳定** → 切换后留足建立时间再读
4. **无 FSR 时 gait event 靠 IMU** → 用足部角速度过零/峰值检测 heel-strike / toe-off，精度略低于足压真值，标注为"IMU 估计事件"
5. **磁力计受铁磁/电机干扰** → V1 无电机，但布线/电池仍可能影响，标定时远离金属
