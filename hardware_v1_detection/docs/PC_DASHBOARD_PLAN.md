# PC 端临床 Dashboard 升级 Plan

> 状态:**计划**（未动代码）。本文件描述 PC 端 app 从"原始信号示波器"升级到"临床 dashboard"的方案。
> 红线：硬件 V1 只做检测，不做介入。本升级只增加**可视化与离线分析**，不引入任何执行器/反馈控制。

## 0. 现状诊断

现有 `demo_app/app.py` 是一个 7-tab 原始信号示波器，信息单薄，根因三条：

1. **只画模长** — `sqrt(ax²+ay²+az²)` 丢掉方向和符号，看不到 pitch 摆动这个步态最关键的形态
2. **7 tab 各看各的** — 对称性分析靠左右对比，却要切 tab，没法同屏
3. **零派生量** — 没有 pitch 角、关节角、步态事件、节律、对称指数，全是原始量纲

目标：实现 L1–L4 算法，把 app 升级为临床 dashboard。

## 1. 验证策略：A + B 双轨

设备最终给偏瘫患者用，但没硬件、没患者前能拿到的数据有限。验证分两轨，**A 给真值，B 给真实形态**：

| 轨 | 数据源 | 验什么 | 有真值 | 边界 |
|---|---|---|---|---|
| **A 仿真合成**（主力） | V13.7 正常轨迹 + 参数不对称版本 → FK 反算 IMU 帧 | L1 角度精度、L2 事件时刻、L4 不对称逻辑（可控负类） | ✅ 精确 | 无真实传感器噪声 / 病理形态 |
| **B 公开集**（补真实） | 帕金森 / 异常步态集（若能联网下到） | 真噪声 + 真实病理不对称下检测还成不成立 | ⚠️ 视频/force 弱真值 | 多数无陀螺 / 单侧，只验局部 |

**分工**：
- A 验"算法几何正确 + 对不对称敏感"。带真值，这是健康人采集给不了的。
- B 补"离开干净仿真、进真实噪声还成不成立"。
- 健康人自采**跳过**：只有正类、没真值，A 的可控负类已替代它。

**为什么仿真是主力而非兜底**：V01-V24 仿真不是玩具轨迹，是有动力学保证的步态（极限环、Floquet、真实接触、能量流都算过）。仿真里关节角、heel-strike 时刻是**精确已知真值**；且能把一侧腿参数改坏，产出**物理上自洽的不对称步态**作为可控负类——比健康人绑沙袋模仿更可控、可重复、可扫描不对称程度。

**学术诚信口径**：A+B 验证 = "算法功能正确"，**不等于临床有效**。L4 临床判定标注"功能已验证、临床有效性待真患者数据确认"，与 `ACCEPTANCE_TEST.md` 对齐，不写过头。

### 仿真能 / 不能验的
- **能当真值验**（健康人采集都给不了）：L1 关节角精度、L2 事件时刻精度、双侧相位对齐、L4 不对称检测逻辑（可控负类）
- **验不了**：真实 IMU 噪声谱/零漂/温漂、足底冲击高频、绑带松动伪运动、软铁/硬铁磁干扰、真实偏瘫的神经-肌肉病理形态（仿真是刚体动力学，造得出运动学不对称，造不出痉挛/协同收缩/本体感觉缺失）

## 3. 算法层（对齐 ALGORITHM_PLAN.md）

| 层 | 实时产出 | 复用 |
|---|---|---|
| L1 姿态 | 各段 sagittal pitch（互补滤波 α≈0.98） | 新写 ~80 行 |
| L1 关节角 | 膝 = 大腿 pitch − 小腿 pitch，髋 = 大腿 pitch − 骨盆 pitch | 段差，直接算 |
| L2 事件 | 左右 heel-strike / toe-off | `common/simulation_framework.py` debounce + `analysis_pipeline/feature_extractor.py` 边沿检测 |
| L3 指标 | 步频、单/双支撑时间、摆动时间、ROM | 新写滚动窗 |
| L4 临床 | Robinson 对称指数、患侧标注 | `gait_medical_system/diagnosis/stroke_gait_classifier.py`（文献基准） |

实时版要点：
- 互补滤波天然递推，适合在线
- L2 在线检测需 ~1-2 步延迟（等事件确认）
- L3/L4 用最近 N 步滚动窗刷新

## 4. 五个 Dashboard 视图（替换 7-tab 示波器）

1. **关节角实时图** — 膝/髋角随时间，左右叠画（红=患侧 / 蓝=健侧），一眼看 ROM 缩小和不对称
2. **步态事件轨道** — 甘特图式条带，左右脚 stance/swing 相位并排，直接看相位差和支撑时间失衡
3. **对称仪表盘** — Robinson SI 大数字 + 阈值色块（<10% 绿 / 10-20% 黄 / >20% 红）+ 患侧判定
4. **关节角循环图（cycle plot）** — 按 heel-strike 归一化到 0-100% 步态周期，叠多步看重复性（Poincaré 思想的临床可视化版）
5. **健康监控条**（保留现状值） — 帧率 / 丢帧 / CRC / jitter / sensor fail 状态灯

布局：上方关节角 + 事件轨道（主区），右侧对称仪表盘 + 监控条，底部 cycle plot。
原 7-tab 原始示波器降级为可选"调试 tab"，不删、不再是主界面。

- **M1 重构骨架** — 拆 pipeline 模块，接口定死（吃 frame，吐 `DerivedSample`），GUI 先只接 L1 pitch 验证解耦。**纯 PC、零硬件依赖，可立即开干**

## 7. B 轨参考（可获取性未联网核实）

> 当前环境网络受限，以下为知识库信息，**链接与存活状态需联网复核**。

| 数据集 | 托管稳定性 | 陀螺仪 | HS/TO 标注 | 双侧 | 致命缺口 |
|---|---|---|---|---|---|
| MAREA | 低（个人页易失链） | ❌ 仅加速度 | ✅ force/光电门 | 部分 | 无陀螺、128Hz、可能下不到 |
| Daphnet FoG | 高（UCI） | ❌ | ❌ 标冻结事件 | ❌ | 标注口径不对 |
| PhysioNet gaitpdb | 高 | ❌ 力敏鞋垫 | ✅ 可推 stride | ✅ | 无 IMU 信号 |
| UCI Daily&Sports | 高 | ✅ 5×IMU | ❌ 仅活动类别 | — | 无事件、25Hz 太低 |

结论：**没有现成完美匹配**（双侧足/小腿/大腿/骨盆 IMU 含陀螺 @200Hz + HS/TO 真值）。B 轨只作局部 sanity check，不进关键路径。主验证压在 A 轨。
