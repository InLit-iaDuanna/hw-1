# 项目定位说明

## 核心理念

hw-1是一个**"仿真研究 → 医疗应用"转化项目**，而不是机器人开发项目。

## 两个并行方向

### 方向1: 仿真研究（V01-V24）

**目标：** 理解被动动态步行的物理本质

**成果：**
- V5: 证明纯被动极限环存在
- V10: 足踝滚动仿生步态（健康步态范本）
- V13.7: 准被动控制能量效率（CoT=0.072）
- V11: 鲁棒性边界（地形容差、扰动容差）
- V17: 真实传感器状态估计算法

**产出：** 健康步态的定量特征库

---

### 方向2: 医疗检测系统（gait_medical_system/）

**目标：** 将仿真成果应用于脑卒中患者康复评估

**技术路径：**
```
仿真定义"健康步态" 
    ↓
患者穿戴传感器行走
    ↓
采集实测数据
    ↓
对比仿真基准
    ↓
量化偏差 → 康复建议
```

**关键模块：**
- `analysis/baseline_extractor.py`: 从V10/V13.7/V11提取健康基准
- `diagnosis/stroke_gait_classifier.py`: 识别偏瘫步态模式
- `data_acquisition/`: ESP32 + IMU数据采集
- `gui/`: 康复评估报告界面

---

## 常见误解澄清

### ❌ 误解1: "这是做双足机器人的项目"

**✅ 正确理解：**
- V22硬件样机是**可选的验证工具**，不是项目主线
- 目的是验证仿真的真实性，不是做产品机器人
- 医疗检测系统才是最终应用目标

---

### ❌ 误解2: "需要做物理样机才能做医疗检测"

**✅ 正确理解：**
- 医疗检测系统**不依赖**V22样机
- 仿真数据已经足够作为健康基准（V10已验证10+步稳定行走）
- 传感器采集的是**患者数据**，不是机器人数据

---

### ❌ 误解3: "传感器是装在机器人上的"

**✅ 正确理解：**
- 传感器穿戴在**患者身上**（弹力绑带固定小腿）
- 采集人类行走数据
- 对比V10仿生步态基准，识别异常模式

---

## 开发优先级

### Phase 1: 医疗检测系统最小可行原型（当前）

**时间：** 2-4周

**任务：**
1. ✅ 创建`baseline_extractor.py`（从仿真提取基准）
2. ✅ 创建`stroke_gait_classifier.py`（步态分类器）
3. ⏳ ESP32固件开发（采集IMU数据）
4. ⏳ Python蓝牙接收程序
5. ⏳ 志愿者测试（健康人 + 模拟偏瘫步态）

**验收标准：**
- 能采集2个IMU数据并蓝牙传输
- 能检测步态周期和计算对称性指数
- 能输出"偏差 + 康复建议"报告

---

### Phase 2: 完整医疗系统（2-3个月）

**任务：**
1. 增加压力鞋垫（足底接触模式）
4. 增加到4个IMU（精确关节角度估计）
2. GUI界面（实时波形 + 报告生成）
3. 数据库（存储患者历史记录）
4. 机器学习模型训练（更多患者数据）

---

### Phase 3: V22样机验证（可选，6-12个月）

**前置条件：** Phase 2完成，且需要验证仿真准确性

**任务：**
1. 制作V22物理样机（¥6000-8000）
2. 实测步态数据
3. 对比仿真参数，修正基准值
4. 发表论文：仿真-实测对比

**可以跳过的情况：**
- 仿真基准已足够可信（V10已验证理论一致性）
- 预算不足
- 时间紧张
