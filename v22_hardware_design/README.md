# V22 — 硬件设计 v1

**状态**：设计文档完成  
**日期**：2026-06-04  
**定位**：2D 矢状面准被动行走机器人硬件设计  
**基于仿真**：V13.7（摩擦补偿 FSM）+ V17（状态估计）

## 1. 设计概述

V22 是 hw-1 项目硬件落地阶段（V22-V25）的第一个版本，目标是将仿真验证的 V13.7 FSM 控制律和 V17 状态估计算法转化为可制造的硬件设计。

### 1.1 设计原则

1. **仿真一致性优先**：硬件参数尽可能接近 V13.7/V17 仿真参数
2. **可制造性**：使用标准件和常见加工工艺，总成本 <8000 元
3. **可调试性**：关键参数可调节（弹簧刚度、质量分布、控制增益）
4. **安全性**：低速行走（<0.5 m/s），2D 约束，软着陆保护

### 1.2 技术规格摘要

| 项目 | 规格 |
|------|------|
| 运动自由度 | 2D（矢状面），侧向导轨约束 |
| 腿长 | 1.00 m（大腿 0.49 m + 小腿 0.51 m）|
| 总质量 | 5.0-6.0 kg（含电池和控制器）|
| 驱动电机 | Dynamixel MX-64AR × 4 |
| 主控单元 | Raspberry Pi 4B |
| 控制频率 | 1000 Hz |
| 行走距离 | ≥5 m（导轨长度）|
| 预算 | 6500-8000 元 |

## 3. 关键设计决策

### 3.1 为什么是 2D 而不是 3D？

**决策**：V22 采用 2D 矢状面设计，使用侧向导轨约束

**理由**：
1. V18/V19/V20 三次 3D 化尝试均未达标（被动、髋外展、步宽控制）
2. 2D 主线（V13.7+V17）已成熟且充分验证
3. 降低首次硬件制作的复杂度和风险
4. 2D 验证成功后可考虑升级到 3D（V22 v2.0）

### 3.2 为什么选择 Dynamixel MX-64AR？

**决策**：使用 Dynamixel MX-64AR 作为主驱动电机

**理由**：
1. V16/V17 仿真中已详细建模和验证该电机参数
2. V13.7 摩擦补偿算法专门针对 MX-64AR 设计（tau_C_eff=0.20 N·m）
3. 高精度编码器（4096 CPR）满足 V17 状态估计要求
4. 成熟的通信协议（TTL/RS485）和开发库（Dynamixel SDK）

**替代方案**：如预算不足，可降级到 AX-12A（约 200 元/个），但需重新调整控制参数。

### 3.3 为什么用 Raspberry Pi 而不是 STM32？

**决策**：初期使用 Raspberry Pi 4B 作为主控

**理由**：
1. 快速原型：Python 代码可直接从仿真移植，开发周期短
2. 调试便利：SSH、ROS 工具链、数据可视化
3. 扩展性强：USB、WiFi、摄像头接口
4. 社区支持：大量机器人项目参考

**缺点**：实时性略差（需实时内核补丁），后期可优化移植到 STM32。

### 3.4 为什么用导轨而不是悬吊？

**决策**：使用侧向导轨约束，而不是悬吊系统

**理由**：
1. 侧向约束刚性强，更接近仿真中的理想 2D 约束
2. 便于调整坡度（整体倾斜导轨）
3. 制作成本低（铝型材 + 直线滑块约 500 元）
4. 安全性高（可在导轨上安装安全绳索）

**缺点**：滑块摩擦力会引入额外阻力（需在系统辨识 V23 中测量并补偿）。

## 4. 与仿真的一致性验证

### 4.1 关键参数对照

| 参数 | 仿真值 | 硬件规格 | 偏差 | 评估 |
|------|--------|----------|------|------|
| 腿长 | 1.020 m | 1.00 m | -2.0% | ✓ 可接受 |
| 总质量 | 5.3 kg | 5.0-6.0 kg | ±5% | ✓ 可接受 |
| 髋部质量占比 | >90% | >90% | 0% | ✓ 符合 |
| 电机扭矩限制 | 4.0 N·m | 4.0 N·m | 0% | ✓ 符合 |
| 编码器分辨率 | 4096 CPR | 4096 CPR | 0% | ✓ 符合 |
| 接触延迟 | <15 ms | <10 ms | - | ✓ 满足 V17 要求 |
| 膝弹簧刚度 | 0.8 N·m/rad | 0.8 N·m/rad | 0% | ✓ 定制 |
| 踝弹簧刚度 | 10.0 N·m/rad | 10.0 N·m/rad | 0% | ✓ 定制 |

**结论**：硬件设计与仿真参数高度一致，预期可直接迁移 V13.7/V17 控制算法。

### 4.2 已知偏差和影响

1. **腿长 -2%**：
   - 影响：步长略短，步频略高
   - 缓解：可在软件中调整 `step_length` 参数

2. **足半径 -4.8%**（0.042 m → 0.04 m）：
   - 影响：足底滚动半径略小，可能影响触地相位
   - 缓解：3D 打印可精确控制，如有问题可重新打印

3. **总质量 ±5%**：
   - 影响：惯性和能量目标略有偏差
   - 缓解：通过配重块微调至目标质量

## 5. 成本分析

### 5.1 总成本构成

| 类别 | 金额 (元) | 占比 |
|------|----------|------|
| 核心部件（电机、控制器）| 4477 | 68% |
| 机械结构（铝管、连接件）| 747 | 11% |
| 2D 约束机构（导轨、滑块）| 650 | 10% |
| 线缆和配件 | 145 | 2% |
| 工具和耗材（实际新增）| 50 | 1% |
| 加工费 | 300-500 | 6-8% |
| **总计** | **6500-7000** | **100%** |

### 5.2 降本方案（如预算不足）

1. **电机降级**：MX-64AR → AX-12A（节省 2600 元）
   - 缺点：扭矩降低，需重新调参
2. **去除导轨**：改用人工侧向约束（节省 500 元）
   - 缺点：行走不自主，仅用于功能验证
3. **控制器简化**：树莓派 → Arduino Mega（节省 200 元）
   - 缺点：需 C++ 移植，开发时间长

**不建议降本的部分**：
- 弹簧（影响被动动力学）
- 传感器（影响状态估计）
- 结构强度（安全性）

## 6. 制作流程建议

### 6.1 阶段 1：采购和加工（1-2 周）

1. 按 BOM 清单采购核心部件（优先级 1）
2. 委托机加工髋部质量块（提供工程图）
3. 自行切割铝管（五金店或自行）
4. 3D 打印脚底（外包或自行）

### 6.2 阶段 2：机械装配（1 周）

1. 组装单侧腿部（大腿-膝-小腿-踝-脚）
2. 测试关节活动范围和弹簧回弹
3. 左右腿连接到髋部质量块
4. 安装躯干和导轨滑块

### 6.3 阶段 3：电气集成（1 周）

1. 树莓派系统安装（Ubuntu + ROS）
2. Dynamixel SDK 配置和通信测试
3. 传感器（接触、IMU）连接和校准
4. 电源系统测试（电池、降压模块）

### 6.4 阶段 4：软件移植（2-3 周）

1. V13.7 FSM 控制器移植（Python → C++ 可选）
2. V17 状态估计器移植
3. 数据记录和监控界面
4. 安全监控（跌倒检测、急停）

### 6.5 阶段 5：调试和测试（2-4 周）

1. 静态测试（悬空状态测试关节控制）
2. 支撑测试（单腿支撑重量）
3. 首次行走尝试（人工辅助）
4. 参数调优（FSM 增益、弹簧刚度）
5. 系统辨识（V23）

**总时长**：约 2-3 个月（兼职）或 1 个月（全职）

## 7. 风险和缓解

### 7.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 硬件参数偏差过大 | 中 | 高 | 严格按仿真参数制作，制作后校准 |
| 控制器实时性不足 | 中 | 中 | 使用实时内核补丁，或降级到 STM32 |
| 机械结构强度不足 | 低 | 高 | 有限元分析验证，使用安全系数 >2 |
| 电机过热 | 低 | 中 | 监控电流和温度，降低扭矩限制 |
| Sim-to-real gap | 高 | 高 | V24 域随机化准备，V23 系统辨识 |

### 7.2 项目风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 预算超支 | 中 | 中 | 预留 10-15% 应急预算，分阶段采购 |
| 交货延迟 | 中 | 低 | 提前采购长交期部件（定制扭簧）|
| 加工质量问题 | 低 | 中 | 选择可靠供应商，收货仔细验收 |
| 时间不足 | 高 | 中 | 合理规划，优先验证核心功能 |
